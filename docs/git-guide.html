Git（ギット）ってなに？

ゲームにたとえると

Gitは、プログラミングのセーブ機能です。
ゲームでボス戦の前にセーブするように、
コードを変える前に「今の状態」を保存しておける。
失敗しても、セーブした時点までいつでも戻れます。

保存する（コミット）

今の状態を
セーブポイントとして記録する

履歴を見る・戻す

過去のセーブポイントを
確認したり、その状態に戻る

保存（コミット）の仕組み

コードを変える
機能を追加、バグ修正など
→
保存する
コミット = セーブ
→
セーブ完了
いつでも戻れる

保存するとき、「何を変えたか」のメモを一緒に残します。
あとで見返したとき「この保存は何の変更だったか」がわかるためです。

履歴を見る・過去に戻す

保存するたびに履歴が残ります。どの保存でも選んで戻れます。

結果画面のデザインを変更 ← 今ここ
7月1日 15:30
正解のアニメーションを追加
7月1日 14:00
クイズの4択ボタンを作成
6月30日 16:20
最初のHTMLファイルを作成
6月30日 14:00

動かなくなっても
安全な状態に戻せる！

エージェントへの頼み方

難しいコマンドを覚える必要はありません。
日本語でお願いするだけでOKです。

保存したいとき

「今の状態をGitに保存して」
「コミットして」でも同じ意味です

履歴を見たいとき

「保存の履歴を見せて」

戻したいとき

「1つ前の状態に戻して」

GitHub Copilot や Codex は、どの言い方でも理解してくれます。

保存するときの流れ

1
コードを変更する
エージェントに頼んで機能を追加したり、
自分で手直ししたり
2
動くことを確認する
ブラウザで確認して、ちゃんと動いてたらOK
3
エージェントに保存をお願いする
「今の状態をGitに保存して。スタート画面を追加した。」
4
保存完了！
セーブポイントができた。安心して次の作業に進める。

やってみよう（体験デモ）

ボタンを押して、エージェントとのやりとりを体験してみよう。

エージェントとの会話

いつ保存すればいい？

こんなタイミングで保存しよう

新しい機能ができたとき
例：「4択ボタンが動くようになった」

バグを直したとき
例：「スコアが増えないバグを直した」

デザインを変えたとき
例：「背景の色を青に変えた」

今日の作業を終えるとき
例：「今日はここまで」

メモの書き方のコツ

「何を変えたか」を短く書く

わかりやすい例：
「スタート画面を追加」
「正解のアニメーションを修正」
「クイズを20問に増やした」

あまり良くない例：
「更新」「変更」「あああ」

まとめ

Gitはコードのセーブ機能。好きなタイミングで保存できる。

履歴が残るから、いつでも過去の状態に戻せる。

操作は「Gitに保存して」と日本語で伝えるだけ。

動くことを確認したら、こまめに保存するのがコツ。
